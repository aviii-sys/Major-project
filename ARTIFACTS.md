# What git tracks, what it does not, and how to get the rest back

Git tracks **code, tests, protocols, reports, tables, figures, configs, training histories and the SHA-256 manifests**. It deliberately does NOT track:

| Not tracked | Why | How to restore or verify |
|---|---|---|
| `data/raw/`, `data/processed/` | large and re-creatable from public sources | run the `fetch_*` and `build_*` scripts (README); raw-file checksums are in `data/raw/MANIFEST.sha256` (the file itself is inside the ignored folder: back it up) |
| model checkpoints (`*.pt`) and run predictions (`predictions.npz`) | binary, tens to hundreds of MB | **back them up separately** (external disk or cloud); each is verified against the hashes in `reports/phase1c|1d|1e/runs/manifest.json` (tracked) |
| `oof_predictions.csv.gz`, frozen Phase 1B predictions and models | large | regenerated by the evaluation scripts from the run predictions; hashes in the frozen `config.json` |
| `dashboard/replay/index.html` | generated (1.4 MB) from the saved predictions; tracking it is optional | `PYTHONPATH=src python scripts/build_replay_dashboard.py` (template, README and screenshots in the same folder are tracked) |
| `dashboard/evaluation/index.html` | generated (0.2 MB) from the result tables; tracking it is optional | `PYTHONPATH=src python scripts/build_evaluation_dashboard.py` (template, README, screenshots and browser_check in the same folder are tracked) |
| `.venv/` | environment | `uv venv` and `uv pip install -r requirements.lock` |

**Important:** git is not a backup for the ignored artifacts. The Phase 1C checkpoints, configs and predictions must be preserved (project rule); keep a copy outside this folder and verify it with `manifest.json`.
If you later want checkpoints in version control, use Git LFS rather than plain git.
